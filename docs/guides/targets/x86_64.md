# Target guide: x86_64

Every command below was run in WSL Ubuntu 24.04 from
a SamCompiler checkout; the output is pasted as it came out,
trimmed only where marked `...`.

## 1. What this target is

| | |
|---|---|
| `-target=` | `x86_64` |
| Data model | LP64: int 4, long 8, pointer 8 |
| ABI | SysV AMD64: arguments in rdi, rsi, rdx, rcx, r8, r9; result in rax |
| Assembler | NASM, `-f elf64`, with `default rel` |
| Linker | `gcc -no-pie` (dynamic, against the host glibc) |
| Runs | natively on the x86-64 host |
| Backend | `codegen_x86_64.c` |

SamCompiler itself is always a native x86-64 program. For this
target it also produces native code, so no cross tools or emulator
are involved.

## 4. Compile a C file for this target

`/tmp/g/add.c`:

```c
int add(int a, int b)
{
    return a + b;
}

int main()
{
    return add(2, 3);
}
```

Compile, assemble and link in one go (`-target=` must come before
the file names):

```
$ ./main -target=x86_64 /tmp/g/add.c /tmp/g/add_x86_64
...
everything compiled fine
nasm -f elf64 /tmp/g/add_x86_64 -o /tmp/g/add_x86_64.o && gcc -no-pie /tmp/g/add_x86_64.o -o /tmp/g/add_x86_64
```

The second argument is first written as the asm file, then
overwritten by the linked binary; the object is `<out>.o`.

To stop after the assembler (keeps the asm), add `object`:

```
$ ./main -target=x86_64 /tmp/g/add.c /tmp/g/add_x86_64.asm object | tail -2
everything compiled fine
nasm -f elf64 /tmp/g/add_x86_64.asm -o /tmp/g/add_x86_64.asm.o
```

`./main` also prints the asm to stdout while it compiles.

## 5. Read the output

`add` from `/tmp/g/add_x86_64.asm`, annotated:

```
default rel                     ; [name] means rip-relative
section .text
global add
add:
pop r11                         ; return address out of the way
push r9                         ; home area: the six argument registers
push r8
push rcx
push rdx
push rsi
push rdi                        ; a lands at [rbp+16]
push r11                        ; return address back, below the home area
push rbp
mov rbp, rsp
movsxd rax, dword [rbp+16]      ; load a, sign-extended to 64 bits
push rax
movsxd rax, dword [rbp+24]      ; load b
push rax
pop rcx
pop rax
add eax, ecx                    ; int add on 32-bit registers
movsxd rax, eax                 ; back to the 64-bit form
push rax
pop rax                         ; return value in rax
pop rbp
ret 48                          ; pop the return address, drop the home area
```

and the call in `main`:

```
lea r11, [add]                  ; callee address
push r11
pop r11
push r11                        ; kept under the arguments
push qword 3                    ; arguments, last first
push qword 2
pop rdi                         ; first argument
pop rsi                         ; second argument
pop r11                         ; callee
xor eax, eax                    ; no vector registers (for variadic callees)
call r11
movsxd rax, eax                 ; the upper half of an int result is undefined
```

The frame at the first instruction of `add`'s body, from gdb:


(gdb prints AT&T syntax; `movslq` is NASM's `movsxd`.)

## 6. Assemble and link by hand

These are exactly the commands the driver runs:

```
$ cd /tmp/g
$ nasm -f elf64 add_x86_64.asm -o add.o
$ gcc -no-pie add.o -o add_manual
/usr/bin/ld: warning: add.o: missing .note.GNU-stack section implies executable stack
/usr/bin/ld: NOTE: This behaviour is deprecated and will be removed in a future version of the linker
$ ./add_manual; echo "exit=$?"
exit=5
```

Why `-no-pie`: the asm takes function addresses with `lea r11,
[name]`, including libc functions. In a PIE that needs the GOT. Without
`-no-pie`, a program that calls `printf` does not link:

```
$ gcc pf.asm.o -o pf_pie
...
/usr/bin/ld: pf.asm.o: relocation R_X86_64_PC32 against symbol `printf@@GLIBC_2.2.5' can not be used when making a PIE object; recompile with -fPIE
/usr/bin/ld: final link failed: bad value
collect2: error: ld returned 1 exit status
$ gcc -no-pie pf.asm.o -o pf
...
$ ./pf; echo "exit=$?"
v=42 s=hi
exit=0
```

The binary is dynamically linked against the host glibc, which is
fine because it runs on the host:

```
$ file /tmp/g/add_x86_64
/tmp/g/add_x86_64: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=e4443620336970768807203da9c7b0371f20f9df, for GNU/Linux 3.2.0, not stripped
```

## 7. Run it

Natively. The exit code is `main`'s return value, modulo 256:

```
$ /tmp/g/add_x86_64; echo "exit=$?"
exit=5
```

## 10. Debug

Native, so plain gdb works. NASM output has no line info; break on
function names and step by instruction:

```
$ cat gdb64.cmd
break add
run
info registers rdi rsi rsp
stepi 10
x/i $pc
info registers rbp rsp
x/4gx $rbp
x/dw $rbp+16
x/dw $rbp+24
$ gdb -q -batch -x gdb64.cmd ./add_manual
```

(output in section 5). Interactively: `layout asm`, `stepi`, `info
registers`, `x/8gx $rsp` to look at the expression stack.

Useful checks:
- at a `call r11`, `p $rsp % 16` must be 0
- after the prologue, `x/6gx $rbp+16` shows the six home-area slots

## 11. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `relocation R_X86_64_PC32 against symbol ... can not be used when making a PIE object` | linked without `-no-pie` | link with `gcc -no-pie` (what the driver does) |
| `missing .note.GNU-stack section implies executable stack` | NASM output has no `.note.GNU-stack` | harmless warning |
| `Target x86_64 has no code generator yet` | a `./main` built before the x86_64 backend | `./build.sh` |
| `x86_64: calls with more than 6 register arguments are not supported` | 7 or more arguments (6 with a struct return) | v1 limit: pass a struct pointer instead |
| `x86_64: an argument must fit one register (no struct arguments by value)` | a struct larger than 8 bytes passed by value (8 bytes or less fits one register and works) | pass a pointer |
| crash walking a `char*` with `*p` (first draft of the backend) | full 8-byte read of a char | fixed: the last dereference reads the value's real width |
| `file` says `ELF 32-bit ... Intel 80386` | `-target=x86_64` placed after the file names is read as the mode word, so the default x86 target is used | put `-target=` first |
